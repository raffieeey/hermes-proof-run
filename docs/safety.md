# Safety and storage reference

- **Exact actions, not guessed ranges.** No numeric interpolation, recombination of independently observed fields, or additional `force` argument is inferred as safe. Nested objects, arrays, null and booleans retain their JSON meaning.
- **Bound observations.** Read facts are matched to their read arguments and session. Only reads before the action contribute to that action's preconditions. Numeric and boolean facts use equality by default; one example cannot establish a general safety threshold.
- **Consumable evidence.** Observations expire after 60 seconds and are consumed before dispatch of a mutation, including competing calls. Refresh reads before each reuse. A read is not a transaction: external state can still change between a read and the mutation. Use a transactional tool for that guarantee.
- **Known failures are not proof.** Host error/cancellation metadata, error JSON and nonzero command exits reject a capture. Missing mutation evidence is rejected. Recorded result fields are checked on guarded replays; a mismatch persists `unproven` and blocks subsequent covered calls, including after reload. This cannot undo the mutation that produced the mismatch.
- **Scope is deliberately narrow.** Known read-only tools and unrelated tools are not generally sandboxed. New tool names, alternate execution mechanisms, external side effects and adversarial models are not contained by this plugin. Multiple bound contracts covering the same tool must all pass and can intentionally conflict. A step with no observed reads provides an argument/evidence check, not an independent world-state guarantee.
- **Guided runs.** A guided run checks a cooperative follower and is not a sandbox: a model can still reach the same effect through a tool the procedure never used. Only the procedure's action tools are gated, and only in the run's session. Reads are advisory unless pinned, except values that a later action reuses from a read: those are resolved only from a successful matching read in the same run and fail closed when missing. Step success is the absence of an error result, not a content match, so result text is not compared. Run state is in memory and a plugin reload ends enforcement. A damaged procedure refuses inspection, pinning and running; duplicate demonstrated values cannot become separate inputs. A co-installed argument-rewriting plugin can leave a run stopped and held; it does not authorize the rewritten arguments.
- **Fail closed on damaged protection.** An invalid/unreadable contract stops mutating calls rather than silently disappearing. Repair it outside the guarded agent or re-record a valid contract as appropriate.
- **Private local persistence.** Contracts are profile-scoped under `plugin_data_dir("proof-run")/contracts/`, with private directories, mode-0600 files, serialized atomic updates and retained versions. Legacy contract storage refuses symlink targets. A pre-existing workflow `runner/` directory symlink is followed; keep that private plugin-data root trusted. Known credential patterns and sensitive named fields are refused, not silently rewritten into a different allowed action. Secret detection is heuristic, not a guarantee that arbitrary credentials or personal data can be recognized. Do not record sensitive tasks.
- **Host boundary.** Historical exact-gate host checks used Hermes `a2db0efb2969d2527d27bf95a53066f5e064d9ad` on Linux. On 2026-11-14 the guided-run command and hooks passed against Hermes `55b0b2611f` with a temporary isolated profile, without a host patch. Workflow checked-execution used the patch noted above. Durable locking uses POSIX file locking. Other operating systems or host versions are not certified by these checks. The host must deliver consistent session and tool-call identity. Hermes' normal approvals remain in force.
